# Rust 对齐原生修复（2026-11-05）

参考原生源码 `a56d52f59516242c009bec75caded1ba9dcfe0dd`、测试规格补充 `836f01f4a0ec04a6c6a6803feee73879f9e397dc`（原生 0.1.4），以及状态恢复修复 `30a731c714602841014835ae3216966e5fbd93b3`。Rust 基线为 `048d291`。

| 原生修复 | Rust 处理 |
| --- | --- |
| HomeKit 主服务 | 设备主服务标记 `primary`，纳入现有拓扑签名；保留原有 AID、主要服务/特征的键和 IID 分配表。被移除的控件 ID 继续保留，不重新编号。 |
| 风扇 | 使用 Fan V2；百分比风速覆盖粗挡位，只提供挡位时按等份映射速度；0% 只关电源，其他速度先设风速再开机。自动模式和童锁并入主服务；保留其他日常模式。 |
| 净化器、空调 | 净化器速度使用最爱挡位，按“设挡位、选最爱模式、开机”执行。空调挡位合并为速度滑块，0% 对应自动；主服务合并童锁、摆风，模式写入同时开机。 |
| 浴霸 | 暖风开关或 Heat/Idle 模式作为制热控制，停止供暖不取消正在运行的 Dry 等其他模式；照明为独立灯泡，可用时带亮度。没有温度时使用暖风开关；超过 38°C 的设定温度保留在客户端。 |
| 辅助开关 | 不再把任意数值的最小值、最大值及加减操作放进 Home。仅保留原生审核过的数值预设。未内置型号最多 10 个日常辅助开关，每组选项最多 6 个；设置类、角度、未审核的厂商私有字段留在客户端。Off/On 两项合为一个开关，同名选项不重复生成控件。 |
| 名称和选项 | 原生中英文词表、注释清理和同名消歧规则用于面板、CLI 和 HomeKit；同名先取具体说明、再加服务限定、最后编号。内置型号保留审核名称并对重复名称编号。 |
| 异常数值 | Rust 的 `as_i64` 等检查本身不会发生 Swift 的整数转换 trap；补齐旧协议非有限值/溢出拒绝、禁止饱和转换后发送、无效范围及步长检查、返回属性 ID 的 `u32` 边界检查。HomeKit 继续在读值、写值和事件路径检查实际协议约束。 |
| 已完成设备及时发布 | 多设备刷新独立发布，常驻轮询最多同时读取 8 台，不给同一台设备排第二次轮询；发现任务不阻塞采集。保留 Rust 的 15 秒成功轮询周期和失败退避。重新发现离线设备，即使 IP 未变，也会提前安排重试。 |
| 恢复事件顺序 | Rust 本来就由每个连接的单一写入者依次加密、发送响应和通知，无需移植 Swift Task 通知链。新增真实加密 TCP + miIO UDP 测试，覆盖已有订阅、错误期间新增订阅、同值恢复和恢复后的无变化抑制。 |
| 监听器一次性启动 | Rust 同步绑定监听器，启动过程由互斥锁保护，没有原生 continuation 的重复 resume 路径。并发启动测试验证只保留一个监听端口和桥身份。 |
| 菜单栏面板 | 排除占位、隐藏和屏幕外图标；没有可用图标位置时改为主屏幕菜单栏右端。全局鼠标回调只采集坐标并投递消息，AppKit 查询和面板关闭在 GPUI 主线程处理。 |

## 验证

- 原生同一组设备规格用于风扇、双键开关、晾衣架及三类浴霸回归。
- 内存凭据仓库和回环 UDP/TCP 验证实际协议，包括风速命令顺序、未变数值的错误恢复、多设备独立发布、重新发现后提前重试、异常返回码和超大属性 ID。
- 显示几何测试覆盖隐藏/屏幕外图标、负坐标显示器及较小可用区域；检查主服务 AID/IID、服务数量上限、格式和取值约束。
- 执行 `cargo test --locked --workspace`、`cargo clippy --locked --workspace --all-targets -- -D warnings`，以及跨平台 Release CI 的测试、打包和包内 CLI 冒烟检查。具体结果以对应 CI 运行为准。

原生 Swift checkout、现有运行中的 Mac 客户端、钥匙串凭据和家庭配对均未修改。协议测试使用模拟设备，不代表所有型号、固件和家庭中枢完成了实机验收。HomeKit 辅助控件的合并/移除与原生一致；使用这些旧控件的家庭自动化在升级后可能需要调整。
